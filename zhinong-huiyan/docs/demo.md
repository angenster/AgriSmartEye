# 固定演示集（E2）

> 目的：让每次演示使用同一批图片，结果可复现，避免临场找图导致结论漂移。
> 清单：`ai-model/data/demo/e2.json`（24 张：20 张常规 + 4 张难例）。

## 1. 构成

- 10 个训练类，每类 2 张（常规）
- 额外 4 张“低 top1-top2 间距”难例，用于展示双引擎仲裁
- 图片不复制进仓库，清单只记录相对 `ai-model/` 的路径；原图仍留在 `data/raw/` 下，
  避免重新分发受数据集许可约束的图片

难例（构建时快照）：

| 真实类别 | CNN 判断 | top1-top2 间距 |
|---|---|---|
| 健康（火龙果） | 火龙果溃疡病 | 0.0118 |
| 健康 | 健康 | 0.0298 |
| 健康（木瓜） | 木瓜花叶病 | 0.0081 |
| 咖啡锈病 | 健康 | 0.0020 |

## 2. 重新生成

```bash
cd zhinong-huiyan/ai-model
../backend/.venv/Scripts/python.exe data/build_demo_set.py --per-class 2 --hard 4
```

选择是确定性的（固定随机种子），同一份 `v1_test.json` 会得到同一批图片。

## 3. 跑一遍（命令行）

```bash
cd zhinong-huiyan/backend
./.venv/Scripts/python.exe -m flywheel.eval_agent \
    --dataset ../ai-model/data/demo/e2.json --per-class 10 \
    --out ../ai-model/reports/demo_run.md
```

当前基线（2026-10-23，未配置 VLM）：

| 指标 | 值 |
|---|---|
| 样本数 | 24 |
| Agent / CNN 准确率 | 83.33% |
| 升级率 | 25.00% |
| 升级成功率 | 0%（无 `VLM_API_KEY`） |
| needs_human 率 | 8.33% |
| 证据核对通过率 | 100% |

> 演示集刻意包含难例，所以准确率低于完整评测集的 94.79%。这说明的是“难例确实难”，
> 不是模型变差。触发升级的 6 张样本准确率只有 33%，正好用来讲“为什么需要第二引擎”。

## 4. 跑一遍（界面）

1. 启动后端与前端，登录；
2. 打开「AI 病虫害识别」，切到「Agent 诊断」；
3. 按 `e2.json` 中 `image_path` 指向的图片逐张上传；
4. 报告里可查看：证据链与出处、`needs_human` 状态、成本字段、实时思考时间线。

演示口径见 README §6。**不要**使用“准确率 95%”“精准施药”这类脱离上下文的表述；
当前不提供化学用药剂量。

## 5. 维护

- 更换生产权重后，难例的选择可能变化，需要重新生成并更新本文的基线表；
- 如果数据集目录被清理，`e2.json` 里的路径会失效，重新执行第 2 节的命令即可。
