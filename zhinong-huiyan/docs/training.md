# 训练报告 v1.1 / v1.2（D2）

> 模型：TropicalPestNet（MobileNetV3-Small 骨干，crop + disease 双头）
> 标签：`v1.1-research`，6 作物 / 12 病害类（其中 7 类有训练数据）
> 日期：2026-10-20
>
> 本文档记录两版：`v1.1-research`（单一来源）与 `v1.2-mixed`（混合来源，当前 production）。

---

## 1. 数据

清单由 [`ai-model/data/build_manifest.py`](../ai-model/data/build_manifest.py) 生成：

| 数据集 | 许可 | 入库 | 来源 |
|---|---|---|---|
| VN-MangoLeaf | CC BY 4.0 | 4,000 | 芒果炭疽病 / 白粉病 / 瘿螨（近似） |
| RoCoLe | MIT | 1,393 | 咖啡锈病 |
| BRACoL（分类视图） | CC BY 4.0 | 699 | 咖啡锈病 / 健康（与 RoCoLe 不同来源） |
| Banana Kaggle | CC BY 4.0 | 217 | 香蕉枯萎病 / 黑星病 / 叶斑病（近似） |
| Banana 乌干达 | Apache 2.0 | 602 | 香蕉叶斑病 / 健康（与 Kaggle 香蕉不同来源） |

- 总清单 6,911 条；训练时按 12 类标签过滤后为 **4,717 train / 602 val / 592 test**（v1.2）。
  v1.1 为 3,688 / 469 / 453。
- 划分按**原图 ID** 分组（80/10/10），增强变体与原图同组，**跨 split 泄漏 0 组**。
- 训练集实际出现 7 类；菠萝（2）、火龙果（1）、木瓜（2）共 5 类**零样本**。
- `mango_xdom` 标记为 `eval_only`，只用于跨域评测，不参与训练。

## 2. 训练配置

| 项 | 值 |
|---|---|
| 骨干 | MobileNetV3-Small（ImageNet 预训练） |
| 输入 | 224×224（训练：RandomResizedCrop/翻转/旋转/ColorJitter；验证：Resize→CenterCrop） |
| 批次 / 轮数 | 32 / 10 |
| 优化器 | AdamW，lr=3e-4，weight_decay=1e-4，CosineAnnealing |
| 冻结策略 | 第 1 轮冻结骨干，只训分类头 |
| 损失 | 两个头分别 CrossEntropy（label_smoothing=0.1）；病害头使用 sqrt 反频率类别权重 |
| 严重度 | **不训练**（`SEVERITY_TRAINED=False`，公开数据无严重度标注） |
| 设备 | CPU（16 线程），v1.2 约 2 分钟/轮 |

## 3. 结果

### 3.1 版本对比（门禁在同一测试集上的评测）

| 版本 | 训练样本 | 同域准确率 | macro-F1 | 说明 |
|---|---|---|---|---|
| `v1.1-research` | 3,688 | 79.73% | 0.628 | 仅 VN-MangoLeaf + RoCoLe + Kaggle Banana |
| `v1.2-mixed` | 4,717 | 94.76% | 0.940 | 增加 BRACoL 与乌干达香蕉集 |
| `v1.3-dr` | 4,717 | 95.27% | 0.915† | 同数据，改用域随机化增强 |
| `v1.4-dragonfruit` | 6,341 | 96.89% | 0.941 | 增加火龙果（8 个训练类） |
| **`v1.5-papaya`** | **7,259** | **95.85%** | **0.940** | 增加木瓜（10 个训练类）+ 作物一致性约束 |

> † v1.3 的 macro-F1 比 v1.2 低 2.5pt，但 bootstrap 检验（2000 次重采样）显示
> 差值的 95% CI 为 **[-0.077, +0.018]，包含 0**，即在该评测集规模下不显著。
> 逐类召回除"香蕉叶斑病"（0.979→0.917，n=48）外，其余 6 类全部持平或提升。
>
> 两版测试集相同（用于门禁对比）。v1.1 在该测试集上偏低是因为它没见过新增来源。
> v1.3 的验证/测试指标：val 94.52% / F1 0.948；test 92.57% / F1 0.927。

### 3.1.1 域随机化增强（v1.3 实验）

`train_manifest.py --aug dr` 在训练时加入：RandomResizedCrop(0.5–1.0)、随机仿射
（±20°、平移、剪切）、RandomPerspective、更强的颜色抖动、随机灰度、高斯模糊、
**随机 JPEG 压缩质量（30–90）**、RandomErasing。色相抖动刻意保持很小（0.05），
因为病斑颜色本身是判别信号。

对照结果（同数据、同超参、同种子）：

| 指标 | v1.2（base） | v1.3（dr） |
|---|---|---|
| 同域准确率 | 94.76% | **95.27%** |
| 同域 macro-F1 | **0.940** | 0.915 |
| 芒果真跨域 | 58.77% | **62.44%** |
| 咖啡真跨域 | 68.83% | **72.17%** |

**结论：域随机化在没有增加任何数据的情况下，把真跨域提升了 +3.3~3.7 个点，
同时同域准确率还略有上升；代价是 macro-F1 的下降（不显著，且集中在单一小类）。**

### 3.1.3 火龙果数据补充（v1.4）

Kaggle 镜像（`ohmahler91`）把类别简化成了 Good/Bad，无法用于 12 类训练。
改用 Mendeley 原版 DF-MOD，通过公开 API 按**文件名前缀**还原类别，
只下载 `Stem_Canker`（540）、`Healthy_leaf`（911）、`Healthy_fruit`（614）三类，
跳过不带类名的增强图。许可 CC BY 4.0。

结果（同 DR 增强，仅增加数据）：

| 指标 | v1.3 | v1.4 |
|---|---|---|
| 训练类数 | 7 | **8** |
| 同域准确率 | 95.27% | **96.89%** |
| 同域 macro-F1 | 0.915 | **0.941** |
| 芒果真跨域 | 62.44% | **66.44%** |
| 咖啡真跨域 | 72.17% | **75.83%** |

**值得注意：跨域集里并没有火龙果图像，但增加一个新作物来源后，芒果和咖啡的
真跨域指标也各涨了约 4 个点。** 这与"来源多样性比单一来源的数量更重要"的判断一致。

### 3.1.5 木瓜数据与作物一致性约束（v1.5）

**木瓜数据**：Mendeley 的 BDPapayaLeaf 同时提供 `.rar` 与 `.zip`，用 ZIP 即可
（机器上没有 RAR 工具）。共 2,159 张，其中 `Anthracnose` 355 → 木瓜炭疽病、
`Curl` 585 → 木瓜花叶病（近似）、`Healthy` 228 → 健康；`BacterialSpot` /
`RingSpot` 不在标签空间内，丢弃。许可 CC BY 4.0。

**加入木瓜后出现了一个真实回退**：芒果真跨域从 66.44% 降到 63.63%，
bootstrap 确认显著（Δ=-2.81%，95% CI [-4.60%, -1.02%]，P=1.000）。
误判明细显示，芒果炭疽病有 **32/360 被判成"香蕉黑星病"**——跨作物错误，
恰好解释了整体约 2.8pt 的下降。

**修复：推理时的作物一致性约束。** 病害标签自带作物前缀，而作物头准确率是 99.78%，
因此可以强制"病害类别必须与预测作物一致"（"健康"无前缀，始终允许）。
效果：

| 真跨域集 | v1.4 | v1.5（未加约束） | v1.5（加约束） |
|---|---|---|---|
| 芒果 | 66.44% | 63.63% | **68.14%** |
| 咖啡 | 75.83% | 75.17% | **80.33%** |

约束不仅补回了下降，还超过了 v1.4。同域指标基本不变（95.85% / macro-F1 0.940）。
开关为环境变量 `MODEL_CROP_CONSISTENCY`（默认开启）。

### 3.1.4 被排除的芒果数据

`binhpt310/mango-combined-dataset`（40,000 张、8 类、CC BY-SA）经 dHash 抽查，
其 Powdery Mildew 类有 **3.6%（9/250）与 MangoLeafBD 近重复**（Hamming ≤3 bit），
训练它会污染 `mango_xdom` 跨域评测，已弃用。芒果目前仍只有 VN-MangoLeaf 一个来源。

v1.3 第一次跑门禁时被旧规则拒绝（macro-F1 固定容差 0.5pt）。但 592 张评测集里
最小类只有 7 张，macro-F1 的 bootstrap 标准误可达数个百分点，固定阈值会把噪声
当回退。因此门禁改为：

- **准确率**：仍用固定容差 0.5pt 的硬门禁；
- **macro-F1**：改用 **bootstrap 显著性检验**——只有差值的 95% CI 整体低于 0
  （即显著回退）才拒绝；
- 严重度：保持原规则。

这个策略不是为某一次结果放宽：它随评测集增大而自动变严，并且避免在小样本上
做出错误的拒绝。旧规则与新规则的结果都会记录在 `eval_runs` 中。

### 3.1.6 菠萝数据与 v1.7 回退诊断（2026-10-23）

**数据**：`pineapple_cand`（PLDD 的 Kaggle 镜像），1,800 张，对应菠萝心腐病 /
菠萝粉蚧两类，入清单 1,450 train / 168 val / 182 test。许可 **CC BY-NC-SA 4.0，
仅研究可用**；可商用的 `pineapple_pldd`（CC BY 4.0，15.8 GB）尚未下载图像。

**两版训练与门禁结果**（同 DR 增强，10 轮）：

| 版本 | 训练样本 | 同域 val | 同域 test | 芒果跨域 | 咖啡跨域 | 门禁 |
|---|---|---|---|---|---|---|
| v1.5-papaya | 7,259 | 93.54% | 91.60% | **68.14%** | **80.33%** | 生产 |
| v1.7-pineapple | 11,354 | 97.38% | 96.83% | 59.63% | 78.17% | 拒绝 |
| v1.7b-pineapple-capped | 8,709 | 97.04% | 97.24% | 55.37% | 79.50% | 拒绝 |

同域明显提升（12 类全部有训练数据），但芒果跨域回退 8~13 个点，远超 0.5pt 容差。

**诊断：退步不在病害头，在作物头。**

按“作物头是否判对”分层统计 `mango_xdom`（1,174 张）：

| 权重 | 作物判对 | 判对时病害准确率 | 作物判错 | 判错时病害准确率 |
|---|---|---|---|---|
| v1.5 | 1,095（93.3%） | **66.21%** | 79（6.7%） | 27.85% |
| v1.7 | 897（76.4%） | 65.89% | 277（23.6%） | 40.79% |
| v1.7b | 882（75.1%） | 65.08% | 292（24.9%） | 32.19% |

作物头判对时，病害头与 v1.5 基本持平（65.08% vs 66.21%）。**全部缺口来自
作物头把芒果判成菠萝**：v1.7b 在芒果跨域集上给出 212 张菠萝（18.0%），
与硬性作物一致性掩码叠加后，这些图的病害候选被限制在菠萝类。

**根因在特征空间，不在分类器。** 用 v1.5 冻结特征训练“菠萝 vs 同域芒果”
线性探针：同域测试准确率 **100%**，但同一探针把 **18.3% 的跨域芒果判成菠萝**
（平均 P(菠萝)=0.224）。即孟加拉来源的芒果在 v1.5 特征空间里本就与菠萝重叠，
新增菠萝类后这部分样本必然被吸走。反向验证：v1.5（从未见过菠萝）对菠萝训练图
判成香蕉 81%、芒果 8.7%——菠萝并不“长得像芒果”，重叠发生在跨域芒果一侧。

**后处理无法补救。** 在 v1.7b 上试了关闭掩码、软作物先验、病害分布反推作物、
新类置信度阈值（tau=0.5~0.95）：

| 策略 | 芒果跨域 | 咖啡跨域 | 菠萝 test 召回 |
|---|---|---|---|
| 现状（硬掩码） | 55.37% | 79.50% | 98.67% |
| 无掩码 | 56.90% | 76.67% | — |
| 软作物先验 | 57.58% | 78.17% | — |
| 病害分布反推作物 | 52.73% | 73.83% | — |
| 新类阈值 tau=0.8 | 60.31% | 80.17% | 97.33% |
| 新类阈值 tau=0.9 | **60.48%** | 80.17% | 93.33% |

最优也只到 60.48%，门禁要求芒果 ≥67.64%（68.14% − 0.5pt）。咖啡倒是能恢复到 80.17%。

**结论与决策**

1. **不要按“作物分支病害头”去修**。分支只改变病害头的组织方式，而病害头是好的；
   292 张作物头判错的图仍会进菠萝分支。
2. 菠萝**暂不上线**，v1.5-papaya 保持 production。真正的前置条件是**芒果的域多样性**：
   当前唯一可商用来源只有 VN-MangoLeaf；MangoLeafBD 为 NC 且正是评测集来源，
   `mango_combined` 因与评测集近重复已排除。
3. 即使精度问题解决，`pineapple_cand` 的 NC 许可也不允许商用。要走商用路线需改用
   `pineapple_pldd`（CC BY 4.0）并重新验证。
4. 可选的下一步：更强的域随机化 / 特征解耦实验（不确定）；或新增许可合规的芒果来源。

## 4. 两条重要的工程修正

1. **零样本类别屏蔽**：5 个没有训练数据的类，其分类头权重是随机初始化的。
   实测中健康的芒果叶片被误判为"木瓜花叶病"（置信度仅 0.196）。
   现在权重里记录 `trained_classes`，推理时把这些类的概率置零再归一化。
   屏蔽后测试准确率从 89.18% 升到 93.82%。
2. **预处理对齐**：训练验证用 `Resize(256) + CenterCrop(224)`，推理原先用
   `Resize((224,224))`，导致同一模型的指标从 0.892 漂到 0.905。已统一。
3. **严重度头不输出**：未训练的严重度头会随机给出"重度"，进而误触发
   "重度必须转人工"的红线，使每次诊断都被强制复核。现在推理层显式返回"未评估"。

## 5. 复现

```bash
cd zhinong-huiyan/ai-model

# 1. 生成清单（需先下载数据集到 data/raw/）
python data/build_manifest.py --raw-root data/raw --out data/manifests/v1.json --include-approx

# 2. 训练（v1.2-mixed）
python training/train_manifest.py --manifest data/manifests/v1.json \
    --epochs 10 --batch-size 32 --img-size 224 --out checkpoints/v1.2-mixed

# 3. 门禁
cd ../backend
python -m flywheel.gate \
    --candidate ../ai-model/checkpoints/v1.1/best.pt \
    --tag v1.1-research \
    --dataset ../ai-model/data/manifests/v1_test.json
```

产物：

- 权重：`ai-model/checkpoints/v1.1/best.pt`（同时复制为 `checkpoints/best.pt` 供后端默认加载）
- 指标：`ai-model/checkpoints/v1.1/metrics.json`
- 门禁记录：数据库 `model_versions` / `eval_runs`

## 6. 已知局限

1. **同域评测，不是真实泛化**：测试集与训练集来自同一批数据集。已补做跨域评测
   （见 [cross_domain_eval.md](cross_domain_eval.md)）：**同域 93.8%，跨数据集只有
   24–50%**。对外表述必须同时给出这两个数字。
2. **类别不平衡**：健康类 1,877 张，香蕉小类仅 23 张，macro-F1 对小类敏感。
3. **5 类未训练**：菠萝、火龙果、木瓜的类别只存在于标签空间，模型不会输出它们
   （推理时已屏蔽）。
4. **严重度未评估**：报告里显示"未评估"，没有任何真假依据。
5. **切片/目标检测缺失**：模型是图像级分类，不输出病斑位置（bbox 恒为 None）。
